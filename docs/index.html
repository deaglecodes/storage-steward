How it works

Three layers, and the agent never waits

While the agent works

Don't make the mess

  • One scratch folder per task, deleted at the end
  • No background output allowed to grow without limit
  • Worktree dependencies cloned with APFS cp -c instead of a fresh install
  • Free space checked before writing more than 1 GB
After every session

Hooks sweep for free

A Stop/SessionEnd hook starts a sweep in the background, at most every 3 hours. The prompt check costs 61 ms and prints nothing unless free space drops below max(20 GiB, 5%).

No slower builds

Keeps the caches you still use

Deleting caches by age alone breaks things, because tools read caches without writing them, so a package you use every day can look a month old. macOS and Linux update a file's access time only when it is older than its modification time.

storage-steward uses that. It sets a stale entry's access time back, and if anything reads the entry, the access time moves forward and the entry is kept. Entries still unread after 7 days are deleted. In the 60-day benchmark this prevented 33–35 re-downloads, for about 2 GB of extra disk.

    Install

    Thirty seconds, then forget about it

    You need Python 3.9 or newer and Claude Code. There's nothing else to install.

    Get the code

    git clone https://github.com/deaglecodes/storage-steward

    Install the skill and hooks

    ./storage-steward/install.sh --retention 21

    This copies the skill to ~/.claude/skills, backs up settings.json, adds three hooks and tests them. --retention is optional; it sets Claude Code's own transcript retention.

    See what it can reclaim now

    python3 ~/.claude/skills/storage-steward/scripts/steward.py scan

    This is a dry run and changes nothing. You can also just ask Claude "why is my disk full?" and the skill handles it.

    FAQ

    Questions

    Will it slow down my prompts?

    No. The prompt hook takes about 61 ms (mostly Python startup) and prints nothing unless free space is low. The cleanup itself runs in a separate background process after a session stops.

    Does it work with Codex, Cursor, or plain cron?

    The script doesn't depend on any one agent. It already cleans Codex and Cursor worktrees and Codex session temp files. Any tool or scheduler can call steward.py sweep. The hooks are specific to Claude Code.

    Will it delete my Claude transcripts?

    Not on its own. Transcripts older than 30 days are a confirm-tier item. --retention 21 sets Claude Code's built-in cleanupPeriodDays, which is Claude Code's own deletion; leave it out to keep the 30-day default.

    How do I see what it removed, or undo the install?

    steward.py report shows the total reclaimed, from a local ledger. steward.py uninstall removes only its hooks, and a backup of your settings is saved on every install.

    Does it run on Linux?

    Yes. Paths fall back to /tmp, ~/.cache and so on. Second-chance eviction relies on relatime, the default on most Linux filesystems. On a noatime mount it detects that and never evicts caches on its own.
